## 代码开发

### 3. 代码编写规范

#### Java 代码规范
- [ ] 遵循 Clean Code 原则（可读性、简洁性）
- [ ] 遵循 SOLID 原则（单一职责、开闭原则等）
- [ ] 使用有意义的变量名和方法名
- [ ] 方法保持简短，职责单一
- [ ] 避免过度复杂的嵌套逻辑

#### 命名规范检查
- [ ] 配置类命名: `Sprival + 组件名 + Configuration`
- [ ] 属性类命名: `Sprival + 组件名 + Properties`
- [ ] 控制器命名: `功能名 + Controller`
- [ ] 服务类命名: `功能名 + Service`
- [ ] 请求体命名: `功能名 + Request`
- [ ] 响应体命名: `功能名 + Response`
- [ ] 实体类命名: `功能名 + Tbl` (数据库) / `功能名 + Model` (业务)

#### 包结构检查
- [ ] 配置类放在 `config/` 包
- [ ] 业务代码放在 `app/` 包
- [ ] 控制器放在 `app/http/controller/`
- [ ] 服务类放在 `app/service/`
- [ ] 数据访问放在 `app/repository/db/{dbname}/`
- [ ] 工具类放在 `app/util/`
- [ ] 支持类放在 `support/`

#### 注解使用检查
- [ ] 配置类使用 `@Configuration`
- [ ] 属性类使用 `@ConfigurationProperties` + `@Data`
- [ ] 控制器使用 `@RestController` + `@RequestMapping`
- [ ] 服务类使用 `@Service`
- [ ] Mapper 使用 `@Mapper`
- [ ] 使用 `@Slf4j` 记录日志（不使用 `@Log4j2`）
- [ ] 使用 Lombok 注解减少样板代码（`@Data`, `@Builder` 等）

#### 文档注释检查
- [ ] 所有公共类添加 JavaDoc 注释
- [ ] 所有公共方法添加 JavaDoc 注释
- [ ] 注释包含方法功能、参数说明、返回值说明
- [ ] 注释包含异常说明（如果抛出异常）
- [ ] 注释包含使用示例（对于复杂方法）

### 4. 配置管理

#### 配置文件检查
- [ ] 配置直接写在 `application.properties`（不加载外部配置文件）
- [ ] Redis/Redisson 使用扁平化配置格式
- [ ] 配置项按组件分组，添加注释
- [ ] 敏感信息使用环境变量或加密存储

#### 配置属性类检查
- [ ] 创建对应的 `@ConfigurationProperties` 类
- [ ] 属性类使用 `@Data` 注解
- [ ] 属性类添加 `prefix` 配置
- [ ] 属性添加 JavaDoc 注释
- [ ] 属性添加默认值（如果合适）

### 5. 日志记录

#### 日志使用检查
- [ ] 使用 SLF4J API (`@Slf4j`)
- [ ] 日志级别正确（DEBUG/INFO/WARN/ERROR）
- [ ] 重要操作记录 INFO 日志
- [ ] 异常记录 ERROR 日志，包含堆栈信息
- [ ] 使用参数化日志（避免字符串拼接）
- [ ] 不记录敏感信息（密码、密钥等）

#### MDC 使用检查
- [ ] 在需要追踪的地方添加 MDC 上下文
- [ ] MDC 添加请求 ID、用户 ID 等关键信息
- [ ] 在 finally 块中清除 MDC (`MDC.clear()`)

### 6. 安全性检查

#### 输入验证
- [ ] 所有用户输入进行验证
- [ ] 使用 `@Valid` 或 `@Validated` 验证请求参数
- [ ] 使用 Bean Validation 注解（`@NotNull`, `@Size` 等）

#### SQL 安全
- [ ] 使用参数化查询（MyBatis `#{}` 而不是 `${}`）
- [ ] 避免 SQL 注入风险
- [ ] 敏感操作添加权限检查

#### 数据安全
- [ ] 密码加密存储
- [ ] 敏感数据传输使用 HTTPS
- [ ] 敏感信息不记录到日志

#### 异常处理
- [ ] 使用全局异常处理器
- [ ] 不向客户端暴露内部错误详情
- [ ] 记录完整的异常堆栈到日志

## 使用说明

### 如何使用此检查清单

1. **开发前**: 完成"开发前准备"部分
2. **开发中**: 按照"代码开发"部分逐项检查
3. **开发后**: 完成"测试"、"构建和运行"、"文档"部分
4. **提交前**: 完成"Git 提交"和"完成检查"部分

### 检查优先级

- **必须检查** ⭐: 安全性、测试、应用启动
- **重要检查**: 代码规范、命名规范、日志记录
- **建议检查**: 文档、性能测试

### 快速检查模式

对于小改动，可以重点检查以下项：
1. 命名规范
2. 包结构
3. 编译和运行
4. 每次修改后重启
5. 不在 ai-home 外写文档
